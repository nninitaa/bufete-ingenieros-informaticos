# Historias de usuario

## 1. Introducción

Las historias de usuario describen las necesidades y funcionalidades del sistema desde la perspectiva de sus usuarios. Permiten identificar qué acciones podrán realizar los clientes y administradores dentro de la plataforma.

Cada historia cuenta con criterios de aceptación que permiten establecer las condiciones necesarias para considerar que la funcionalidad cumple con lo esperado.

## 2. Historias de usuario

### HU-01: Consultar información del bufete

**Como:** Cliente.

**Quiero:** Consultar información general sobre el bufete.

**Para:** Conocer quiénes son, qué servicios ofrecen y a qué áreas de informática se dedican.

**Criterios de aceptación:**
- La página debe mostrar información general del bufete.
- La información debe ser clara y fácil de entender.
- El usuario debe poder acceder a esta información desde la página principal.
- La sección debe permitir continuar navegando por el resto de la página.

### HU-02: Consultar servicios informáticos

**Como:** Cliente.

**Quiero:** Consultar los servicios que ofrece el bufete.

**Para:** Conocer las diferentes soluciones informáticas disponibles.

**Criterios de aceptación:**
- El sistema debe mostrar una lista de servicios.
- Cada servicio debe tener un nombre.
- Cada servicio debe contar con una descripción.
- El usuario debe poder seleccionar el servicio que le interese.

### HU-03: Obtener información sobre un servicio

**Como:** Cliente.

**Quiero:** Seleccionar un servicio informático.

**Para:** Obtener información más detallada sobre este.

**Criterios de aceptación:**
- El usuario debe poder seleccionar un servicio.
- El sistema debe identificar el servicio seleccionado.
- El sistema debe mostrar información relacionada con dicho servicio.
- La información debe presentarse de manera ordenada.
- El usuario debe poder seleccionar otro servicio posteriormente.

### HU-04: Consultar información de los ingenieros

**Como:** Cliente.

**Quiero:** Conocer a los ingenieros que forman parte del bufete.

**Para:** Conocer sus áreas de trabajo y especialización.

**Criterios de aceptación:**
- El sistema debe mostrar los ingenieros registrados.
- Cada profesional debe tener información básica.
- La información debe estar organizada.
- El usuario debe poder consultar los diferentes perfiles.

### HU-05: Consultar proyectos realizados

**Como:** Cliente.

**Quiero:** Consultar los proyectos realizados por el bufete.

**Para:** Conocer ejemplos de trabajos y soluciones desarrolladas.

**Criterios de aceptación:**
- El sistema debe contar con una sección de proyectos.
- Debe mostrar los proyectos disponibles.
- Cada proyecto debe contar con una descripción.
- La información debe presentarse de forma organizada.

### HU-06: Enviar una consulta

**Como:** Cliente.

**Quiero:** Enviar una consulta mediante un formulario.

**Para:** Solicitar información sobre los servicios del bufete.

**Criterios de aceptación:**
- El formulario debe contar con los campos necesarios.
- Los campos obligatorios deben validarse.
- El usuario debe poder escribir su consulta.
- El sistema debe indicar si la información fue enviada correctamente.

### HU-07: Ingresar al área administrativa

**Como:** Administrador.

**Quiero:** Iniciar sesión en el sistema.

**Para:** Poder administrar la información de la página.

**Criterios de aceptación:**
- El administrador debe ingresar sus credenciales.
- El sistema debe validar las credenciales.
- Si son correctas, debe permitir el acceso.
- Si son incorrectas, debe mostrar un mensaje indicando que los datos no son válidos.

### HU-08: Administrar servicios

**Como:** Administrador.

**Quiero:** Agregar y modificar servicios.

**Para:** Mantener actualizada la información que aparece en la página.

**Criterios de aceptación:**
- El administrador debe poder agregar un servicio.
- Debe poder modificar la información de un servicio.
- Los cambios deben guardarse correctamente.
- La información modificada debe mostrarse posteriormente a los usuarios.

### HU-09: Administrar información de los ingenieros

**Como:** Administrador.

**Quiero:** Actualizar la información de los ingenieros.

**Para:** Mantener actualizados sus perfiles dentro de la página.

**Criterios de aceptación:**
- El administrador debe poder agregar información de un ingeniero.
- Debe poder modificar información existente.
- Los cambios deben guardarse correctamente.
- La información actualizada debe aparecer en la página.

### HU-10: Administrar proyectos

**Como:** Administrador.

**Quiero:** Agregar y modificar proyectos realizados.

**Para:** Mantener actualizado el portafolio del bufete.

**Criterios de aceptación:**
- El administrador debe poder agregar proyectos.
- Debe poder modificar la información de los proyectos.
- Cada proyecto debe contar con información descriptiva.
- Los cambios deben guardarse correctamente.

### HU-11: Actualizar información general

**Como:** Administrador.

**Quiero:** Modificar la información general del bufete.

**Para:** Mantener actualizados los datos que aparecen en la página principal.

**Criterios de aceptación:**
- El administrador debe poder modificar la información.
- Los cambios deben guardarse correctamente.
- La información actualizada debe mostrarse a los usuarios.

## 3. Consideraciones generales

Las historias de usuario constituyen una referencia para el diseño y desarrollo de las funcionalidades de la plataforma.

Sus criterios de aceptación permiten identificar las condiciones que deberá cumplir cada funcionalidad y facilitan la posterior elaboración de diagramas técnicos y la verificación de los requisitos establecidos.
